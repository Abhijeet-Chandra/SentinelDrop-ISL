This report is reconciled against the submitted August 2026 synopsis and the code in this isolated worktree. Status refers to implementation, not final physical-device/deployment acceptance. The synopsis defines offline transfer of text, image evidence and voice-note transcripts; QR identity verification; X25519/HKDF; AES-256-GCM; replay/tamper/flood controls; hash-chained logging; PyShark/Wireshark analysis; six image metrics; and comparative performance measurements.

## Important design explanations

- **Payload confidentiality:** The browser stores its X25519 private key as a nonextractable CryptoKey in IndexedDB. After reciprocal fingerprint approval, each side derives an X25519 shared secret, uses HKDF-SHA-256 with the session and direction identifiers, then AES-256-GCM encrypts the payload. API authorization uses the account/session record but does not receive the private key or derived AES key.
- **Metadata integrity:** Transfer metadata is encoded as AES-GCM additional authenticated data. A mismatch, altered ciphertext, or invalid authentication tag fails browser decryption. The server persists ciphertext and transfer metadata for relay/admin review.
- **Replay protection:** The API authenticates the user against a durable peer session, reserves `(session, sender, nonce)` uniquely, limits queued messages per recipient, and acknowledges receive after browser authentication/decryption.
- **Audit signature wording:** The transfer row carries a server-generated Ed25519 attestation over audit metadata. It is not a sender signature. The separate signature lab demo uses a temporary key and does not persist a private key.
- **Image metrics:** AES-GCM is an authenticated stream construction, not a custom classical image cipher. Ciphertext-byte visualizations and entropy/correlation are illustrative. Controlled NPCR/UACI under same key/nonce are not expected to match traditional image-cipher targets; production nonce reuse is rejected. Exact authenticated decryption yields MSE 0 and infinite PSNR.
- **Hash properties:** Preimage/collision wording in the dashboard distinguishes definitions from bounded 12-bit toy demonstrations; these runs do not test full SHA-256 resistance.
- **Monitoring:** App events and PCAP packet-rate thresholds are indicators. Seven UI lab scenarios are deterministic safe simulations; they do not establish resistance to every real-world attack.
- **Voice:** Normal voice notes are transcribed on the sender device with Vosk WebAssembly. The authenticated model archive is cached in browser IndexedDB after first use; while offline, recognition can run locally, but encrypted transfer still needs the relay API. Only aggregate audio-size and elapsed-time metadata is optionally logged. The Admin benchmark is separate and intentionally uploads a selected sample to measure backend Vosk/AES processing.
